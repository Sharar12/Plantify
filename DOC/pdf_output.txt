Abstract
This practicum report present the project management and planning for Plantify a full stack plant nursery e-commerce web platform which was developed using Laravel Next.js React TypeScript and MySQL. The application serve four different user roles Customer, Specialist, Delivery Personnel, and Admin, which enable plant browsing cart and order management, expert Q&A, delivery tracking, inventory and category administration and business analytics features. The study mainly focus on project planning aspects such as risk management, software size estimation, scheduling and cost analysis. Using Function Point Analysis (FPA) methodology, the functional size of the system were calculated as 160 Adjusted Function Points (AFP). The project was completed within 13 weeks using Agile Scrum inspired incremental development process with four sprints. A total of 8 risks were identified, analysed and addressed using comprehensive Risk Mitigation Monitoring and Management (RMMM) plans. The estimated total cost range from 3,800 to 63,800 Bangladeshi Taka (TK), reflecting the academic environment and usage of free open source tools only. The report also describe feasibility studies, requirement engineering, including 24 user requirements, 33 functional requirements and 16 non functional requirements, system design quality assurance with 60 test cases having 100% pass rate, and ethical and sustainability considerations. This project was developed during my internship at Globix Tech and it helped me gain practical experience in both full stack development and software project management for real world applications.

1.1 Background of the Study
Traditionally, plant nurseries was mostly depending on manual record keeping, in person sales and paper based inventory tracking. As the nursery grow bigger, maintaining accurate stock levels, managing customer orders handling plant care enquiries and coordinating deliveries becomes more difficult and confusing. In today's digital landscape customers expects the convenience of browsing plants online reading reviews asking questions before purchase and getting doorstep delivery too.
Plantify is a full stack plant nursery management application which was developed to solve these challenge's. It provide a centralised digital platform where nursery businesses can manage their plant inventory, process customer orders, facilitate specialist consultations coordinate deliveries and access business insight's through analytics all by using a modern web interface. The application serve four distinct user roles which are Customers, Specialists, Delivery Personnel and Administrators.
This report document's the project management and planning aspects of the Plantify application covering risk management, project estimation, function point analysis scheduling and cost estimation.
1.2 Methodology
1.2.1 Data Sources
The project planning and estimation for Plantify was drawn from five primary data source's:
 Project Codebase Analysis: Direct examination of the Plantify source code including backend controllers, models, routes database migrations and frontend components.
 Database Schema: Analysis of all 8 database tables such as users, plants, categories, orders, order_items, reviews, questions and wishlists from SQL dump and Laravel migration files.
 API Route Analysis: Inventory of more then 20 API endpoints across Auth, Plants Orders, Reviews, Questions, Wishlists Categories and Upload modules.
2|Page

 Project Documentation: Review of documents like README.md, ARCHITECTURE_FIX_SUMMARY.md VERIFICATION_REPORT.md, Project_Tree.md and configuration files.
 Industry Standards & Market Research: Application of IFPUG Function Point Analysis standards for software sizing standard software engineering project management practices for risk analysis and cost estimation plus Bangladesh/regional salary data for estimating personnel cost.
1.3 Objectives
1.3.1 Broad Objective
To develop a comprehensive project management and planning report for the Plantify full stack plant nursery management application covering risk identification and mitigation software size estimation using Function Point Analysis, project scheduling and cost estimation in Bangladeshi Taka (TK).
1.3.2 Specific Objectives
The specific objectives of this report is:
1. Risk Management: Identify analyse and plan mitigation strategies for all potential technical operational schedule and external risks which could impact the Plantify project.
2. Software Size Estimation: Apply Function Point Analysis methodology to measure the functional size of Plantify based on External Inputs, External Outputs External Inquiries Internal Logical Files and External Interface Files.
3. Complexity Analysis: Determine the complexity of each transaction and data function based on Data Element Types (DETs), Record Element Types (RETs) and File Types Referenced (FTRs).
4. Effort and Duration Estimation: Calculate Adjusted Function Points estimate required person months of effort and determine project duration based on team size with productivity benchmarks.

5. Project Scheduling: Create a detailed 13 week Gantt chart with 4 sprints covering all development phases from planning through testing and deployment.
6. Cost Estimation: Prepare a comprehensive cost breakdown covering personnel hardware software and other expenses in Bangladeshi Taka.
7. Risk Mitigation Planning: Develop a Risk Mitigation Monitoring and Management (RMMM) plan for the highest priority risks including defined triggers owners contingencies and success criteria.
1.4 Process Model
1.4.1 Reason for Choosing the Required Process Model
The Plantify project follows a Agile Process Model using Scrum inspired sprint based incremental development. Although it was intended for a single developer and academic context this approach was choosen because of several reasons.
 Modular Architecture: The application has clear separable modules like Auth, Plants Orders and Reviews which can be developed incrementally in different sprints allowing the developer to focus on one module at a time without context switching overhead.
 User Role Complexity: Four distinct user roles requires iterative refinement, working in sprints helps the developer perfect role specific views and permissions sequentially.
 Evolving Requirements: E commerce features like cart checkout and wishlist benefits from iterative feedback. In university setting informal peer or supervisor feedback can be gathered after each sprint and incorporated immediately.
 Technology Stack: Laravel and Next.js supports rapid prototyping and incremental feature delivery which aligns perfectly with agile practices.
 Personal Sprint Discipline: Even as a solo developer simple tools like GitHub Project board can simulate sprint planning daily self standups and retrospectives preventing procrastination and ensuring consistent progress.
4|Page

 Risk Mitigation: The iterative nature of agile allow early detection and mitigation of risks like authentication security and cart state management within early sprints without requiring team alignment.
1.4.2 Sprint Structure
The project is organised into 4 sprints over 13 weeks:
 Sprint 1 (Weeks 1�3): Planning & Backend Foundation -- project setup database design Laravel API for Auth Plants Categories Upload, Next.js initialisation and plant browsing UI.
 Sprint 2 (Weeks 4�6): Frontend Core & E Commerce -- login/register pages plant detail page cart checkout orders wishlist and profile management.
 Sprint 3 (Weeks 7�9): User Features & Social -- reviews questions & answers specialist dashboard delivery role category management and PHPUnit tests for critical controllers.
 Sprint 4 (Weeks 10�13): Administration Testing & Deployment -- RBAC middleware admin dashboard analytics integration testing security hardening and final documentation.
1.4.3 Scrum Ceremonies (per Sprint)
Each sprint includes four key ceremonies which are Sprint Planning to define backlog and estimate tasks, Daily Standups for tracking progress and blockers Sprint Review to demonstrate completed work and gather feedback plus Sprint Retrospective to reflect on the process and identify improvements for the next sprint.

The project is technically feasible. The RESTful API architecture is suitable for more then 20 endpoints covering CRUD operations. Image upload using Laravel filesystem is

All software tools like Laravel, Next.js MySQL Tailwind CSS VS Code and Git are free and open source. As a standalone system without third party integrations it runs on standard LAMP/LEMP stack. Maintenance is simplified by Laravel database migrations and modular codebase. The system can scale vertically or horizontally as business grows database backup are provided through SQL dumps and there is no special regulatory requirements for nursery e commerce application. It can operate 24/7 with admin and delivery roles managing orders asynchronously.

4.1 Software Analysis Pattern
 MVC Architecture � Using Laravel on backend is composed by 3 layers: 1. Model: The eloquent models (User, Plant, Order etc) define data structure and business logic. 2. Controller: Handles HTTP requests, validate input, interact with models and returns JSON responses. 3. View: This removes JSON and uses next.js visual rendering.
 Repository Pattern � Data access is encapsulated within Eloquent model classes: 1. Clean query methods (Plant::all(), User::where(...)->first()). 2. Relationship definitions (belongsTo, hasMany) on model level. 3. Mass-assignment protection through $fillable properties. 4. The automatic timestamp management which handled by framework itself.
 RESTful API Pattern � All backend endpoints follows REST conventions: 1. Stateless communication each request carries all necessary informations. 2. Resource-oriented URLs like /api/plants, /api/orders/{id} etc. 3. The standard HTTP verbs used for CRUD operations properly. 4. Consistent JSON responses across all endpoints are maintained.
 Client-Server Architecture � These system is separated into two main folders. which are frontend and backend: 1. Frontend: run in browser and communicate with Laravel server through HTTP/HTTPS. 2. Backend: These processes requests to interact with MySQL and return JSON response while UI handled by frontend.
 Component-Based Architecture � Next.js frontend is built from reusable selfcontained components: 1. Header.tsx: provide navigation, user menu and cart icon. 2. PlantCard.tsx: render individual plant cards with image name price and rating. 3. Page Components: This combines the elements into full pages like home cart admin dashboard etc.
 Data Access Pattern � Database uses Active Record pattern of Eloquent: 1. Each model represent a database table and instance represent rows. 2. The relationships defined using belongsTo() and hasMany(). 3. Eager loading (with()) avoid N+1 query problem.

8.1 System Quality Management 8.1.1 Software Quality Management Process
 Quality planning: It is defined through 7 clear objectives. These 7 objectives are functional correctness, API reliability, frontend rendering, data integrity, security, performance and usability. These guides the system development in a structured way and helps maintain overall quality. The objectives ensure that the system behaves correctly under expected conditions and also remains stable when the load increases or when new features are added.
 Quality assurance: It is maintained through code reviews, coding standards, static analysis, security, migration and documentation reviews. These practice helps to ensure that the codebase remains clean, consistent and maintainable in the development lifecycle.
 Quality control: It is achieved through multiple levels of testing including unit testing integration testing system testing user acceptance testing and regression testing. Each level of testing helps to identify issues at different stages of development and ensures that new changes do not break existing functionality.
 Quality standards: Adheres strictly to: TypeScript, ESLint, WCAG 2.1 AA and Laravel coding conventions to satisfy requirements.

They are Customer, Specialist, Delivery Personnel and Admin. Plantify provides one platform for managing plant inventory selling plants online getting advice from specialists tracking orders and analyzing business performance.

10.2 Proposed System Benefits
Plantify makes life easier for everyone at the nursery. It streamlines the day-to-day work and gives customers a far better experience.
For the nursery business Plantify gets rid of the paper system and uses a real-time digital platform instead. The inventory is managed from one place that automatically updates the stock when an order is placed. This means we do not oversell and we do not have to count everything by hand. It makes the system more reliable. Helps us keep track of our inventory better.

The online storefront lets customers buy from us from over the country at any time of day. We are not limited to people who can come to our physical shop. The analytics dashboard shows us how money we are making from orders and which plants are the most popular. This helps us make decisions based on what is really happening.
Using Plantify also reduces the amount of work we have to do as administrators. The system for reviewing and answering questions helps our customers trust us more. Plantify is really helpful for the nursery business because it makes everything easier to manage and it helps us reach customers.
Customers get easy access to the full plant catalog with detailed care tips and reviews. They can shop from any device with obvious pricing, wishlist support, and full order tracking. The review and question system also helps customers learn more before buying.
Specialists get a dedicated dashboard for plant management categories and customer questions. All CRUD operations are centralised, and image upload is simple. Their answers remain permanently visible, which reduces repeated queries and improves knowledge sharing.
Delivery personnel only see assigned orders, which removes confusion. A simple interface allows them to update order status from pending to delivered, which keeps the system updated without manual calls.
Administrators get full control over users, plants, orders, and categories from one dashboard. An analytics system helps decision-making for inventory marketing and resource planning. Role-based management ensures proper control across the system.
10.3 Limitations of the Project
Plantify works fine as a full academic prototype, but it still has a few limitations before real production use.
The primary issue is the absence of authentication middleware and role-based access control, which results in insecure endpoints and potential privilege escalation risks. The payment
113 | P a g e

gateway isn't added, so everything works only with offline orders. The system lacks a password reset mechanism and does not provide email notifications for order updates.
The cart is saved in localStorage, so it can disappear on other devices. The search and filtering features are basic, and the plant image gallery has limited functionality. There's no automated testing, so bugs can increase in future updates.
Finally, the system is designed for a single nursery and does not support a multi-vendor marketplace structure.
